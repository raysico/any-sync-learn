> **「先摸清边界，再决定要不要改协议。当前最缺的是『边界在哪』这个事实，而不是『维护自己协议』这个动作。」**

### 5.2 替换方法

你有两条路，第 1 期决策时选一条：

| 方法 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 重打镜像** | 写 `Dockerfile`：`FROM alpine` + `COPY bin/xxx`，`docker build` 后改 compose 里的 `image:` | 干净、可重复、接近生产 | 每次改代码要重新 build 镜像 |

```yaml

```

> ```bash

> docker exec any-sync-dockercompose-any-sync-node-3-1 ls -la /bin/ | grep any-sync

白名单有 7 个值。**它们的行为差异对产品意味着什么？**
比如：`anytype.techspace` 是不是官方客户端放自己元数据的地方？你能不能用 `any.onetoone` 做私聊？

- [ ] 7 个类型逐个判定「我能用吗 / 用了会怎样」

#### 边界 3：多端同时改同一个对象会发生什么？

这是同步系统的**根本能力**。
- 两台设备同时改同一个对象 → 结果是什么？（后写覆盖？合并？报错？）
- 冲突解决靠 tree 节点还是 consensus 节点？
- any-block 的 CRDT 在什么层面介入？

**测法**：用 `whynownote-heart` 起两个进程（模拟两台设备），同时改同一个对象，观察最终状态。

- [ ] 有可重复的冲突实验结果
- [ ] 能说清冲突在哪一层解决

#### 边界 4：权限模型能做到多细？

- 只能做到「空间级」权限，还是能到「对象级」？
- ACL 记录是链式的吗？能撤销吗？
- 能不能实现「只读成员」「限时访问」？

- [ ] 能说清权限的最小粒度
- [ ] 能判断是否能满足你产品的协作需求

#### 边界 5：离线与恢复行为

- 客户端离线多久后回来还能同步？
- 节点重启后数据还在吗？（你有 `storage/` 目录挂载，应该还在）
- **如果一个 tree 节点永久丢失，数据会丢吗？**（副本因子相关）

- [ ] 有明确的离线时长与恢复行为结论
- [ ] 能回答「数据可靠性」这个产品必答题

### 8.3 实验纪律（避免自我欺骗）

| 纪律 | 说明 |
| --- | --- |
| **一次只改一个变量** | 不要同时改代码和配置，否则不知道是谁导致的 |
| **记录原始输出** | 不要只写「失败了」，要贴错误原文 |
| **可重复** | 每个结论至少跑两次，第二次用干净的环境 |
| **区分「我不知道」和「不支持」** | 测不出来 ≠ 不支持。测不出来要写 ❓，不能写 ❌ |
| **失败也是结论** | ❌ 的条目和 ✅ 一样有价值，甚至更有价值 |

### 8.4 本期验收

- [ ] 判定矩阵至少覆盖 P0 与 P1 的 RPC（不要求 112 个全覆盖）
- [ ] 五个优先边界问题都有判定
- [ ] 每个 ❌ 都有错误原文 + 源码依据
- [ ] 剩余未验证项有明确清单（写清还有多少个 ❓）

## 9. 第 7 期：结论与决策（1 天）

### 9.1 用第 6 期的矩阵重新评估三个台阶

| 台阶 | 你 MVP 文档里当时的判断 | 现在用实测事实重新判断 |

## 10. 风险登记表

| # | 风险 | 影响 | 缓解 |

## 12. 最小可行路径（如果只有 3 天）

只做这三件，就能拿到「源码构建」的完整闭环：

| 天 | 做什么 | 拿到什么 |
| --- | --- | --- |
| **第 1 天** | 第 1 期全部（PATH + git clone + 版本基线） | 版本可追溯的地基 |
| **第 2 天** | 第 2 期（编译出二进制） | `bin/` 下的可执行文件 |
| **第 3 天** | 第 3 期的同步节点替换（只换 node-3 一个） | **自己编译的代码跑在真实网络里** |

**为什么这三天值得优先做**：完成之后，「从源码构建」这个目标就算真正达成了，而且你会获得一种能力——**改一行代码 → 编译 → 替换 → 观察行为变化**。这个反馈闭环是后面「能力边界」和「如何使用能力」的全部基础。

## 14. 明天就可以开始的第一步

如果你明天只有 2 小时，做这个：

```bash
# 1. 修 PATH（15 分钟）
cat >> ~/.zshrc <<'EOF'

# --- Go 工具链（any-sync 源码构建）---
export PATH="$HOME/.local/go/bin:$PATH"
EOF
source ~/.zshrc

# 2. 验证（必须开新终端窗口再验一次）
go version

# 3. 看当前 Go 环境（记录基线）
go env GOPROXY GOPRIVATE GOPATH
```

**然后回答一个问题**：你的源码锁哪个版本？用下面这条查官方推荐，和你正在跑的 v0.13.0/v0.13.1 对比：

```bash
curl -s https://puppetdoc.anytype.io/api/v1/prod-any-sync-compatible-versions/ \
  | python3 -c "import json,sys; d=json.load(sys.stdin); print(json.dumps(d[max(d,key=int)],indent=2))"
```

这两个动作加起来 30 分钟，但它们决定了后面 13 天的效率。**这就是第 1 期为什么排在最前面。**
