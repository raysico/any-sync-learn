## 4. 第 3 块（11:45–12:45，60 分钟）：看懂你刚部署了什么

> 这一块**完全不需要 Docker 是健康的**，是纯阅读 + 填表。就算第 2 块失败也能全做完。

### 4.1 目标

不看任何代码，用「看图说话」的方式理解：一套 any-sync 网络由哪些角色组成、数据怎么流动。

### 4.2 用生活化的比喻理解（先读这段）

把 any-sync 网络想象成**一个城市的档案与户籍系统**：

| 真实角色 | 在他的城市里是谁 | 他负责什么 | 没有他会怎样 |
| --- | --- | --- | --- |
| **coordinator** 协调节点 | 户籍警 | 登记「有哪些空间（space）」「谁是成员」「哪个节点服务哪个空间」 | 新成员加不进来，空间建不了 |
| **consensus** 共识节点 | 公证员 | 监督户籍警的登记行为，防止它一个人说了算 | 户籍警可能被篡改或单点作弊 |
| **node** 同步节点 | 仓库管理员（有 3 个） | 存文档数据、互相转发、给客户端取数据 | 你的文档没地方存、同步不了 |
| **filenode** 文件节点 | 档案管理员 | 专门存大文件（图片、附件），配合仓库和缓存 | 图片附件传不上去 |
| **Garage** 对象存储 | 总仓库 | 真正落地存放文件本体的货架 | 文件没地方放 |
| **Redis Stack** | 索引卡柜 | 快速回答「这个文件我这儿有吗」（用布隆过滤器） | 档案管理员干不了活，直接罢工 |
| **MongoDB** | 名册本 | 给户籍警和公证员记录名册 | 户籍警和公证员无法工作 |
| **netcheck** | 体检医生 | 反复检查各角色之间通信是否正常 | 你不知道网络到底通没通 |

**记住这张表，今天的学习目标就达成一半了。** 明天你看到任何 any-sync 的讨论，至少知道大家在说哪个角色。

### 4.3 数据怎么流动（读一遍，理解方向即可）

**场景 A：你上传一个文档**
```
你的客户端 → 同步节点(node) → 同步节点之间互相同步 → 其他设备上的客户端
```
（协调节点不在数据路径上，它只管「谁是谁」）

**场景 B：你上传一张图片**
```
你的客户端 → 文件节点(filenode) → 先问 Redis「我有这个文件吗？」
                                   → 没有则存进 Garage，并在 Mongo 记账
```

**关键洞察（这是设计上很重要的一点）**：
> **Redis 不是「必须永不丢失」的数据。** 官方设计里，索引信息同时写在 Garage 里一份，Redis 只是「加速卡柜」。所以 Redis 挂了可以从 Garage 重建——这解释了为什么官方给 Redis 设了 256MB 的小内存上限，且内存满了宁可「拒绝写入」也不「丢弃数据」。

## 5. 第 4 块（13:45–14:45，60 分钟）：认识配置文件和节点类型

### 5.1 目标

理解「一份配置文件就定义了一个网络」，并认识 7 种节点类型。

### 5.2 关键概念：`client.yml` 是什么

`client.yml` 是**客户端接入自建网络的钥匙**。它里面写明了：

- **networkId**：这个网络的唯一编号（相当于身份证号）。客户端靠它对号入座，连错网络就进不去。
- **nodes 列表**：这个网络里有哪些节点、地址是什么、分别是什么类型。
- **签名密钥信息**：用来验证这份配置是真的、没被人篡改。

**一句话**：把 `client.yml` 交给客户端，客户端就知道「去哪连、信任谁」。今天第 5 块就是把它交给 Anytype。

## 8. 常见故障对照表（零基础版）

> 遇到报错先在这里找。**找不到对应项，就不要自己试**——记录原文，留给我判断。

| 你看到的 | 真实含义 | 怎么办 |
| --- | --- | --- |
| `Cannot connect to the Docker daemon` | Docker 引擎还没启动完 | 回第 1 块步骤 2 等 2 分钟，重试 |
| `Docker Desktop starting...` | 引擎正在启动 | 正常，等 1–3 分钟 |
| `Permission denied` + 某个 `.sh` 文件 | 脚本没有执行权限 | 执行 `chmod +x 那个文件名`，再重跑 |
| `port is already allocated` | 端口被别的软件占了 | 记下报错里的端口号，发给我（本机实测这些端口当前空闲，出现说明有变化） |
| 容器显示 `Restarting` 反复重启 | 服务启动失败 | 记下哪个服务，跑 `docker compose logs 服务名`，把最后 20 行发我 |
| 容器显示 `Exited (1)` | 服务启动后立刻退出 | 同上 |
| `netcheck` 日志里一堆红字，但容器都 `Up` | 可能只是首次启动慢 | 等 3–5 分钟再看一次，仍失败则按第 2 块失败分支存日志 |
| `docker compose up -d` 后终端一直刷日志不返回 | 命令漏了 `-d` | `Control + C`，重跑带 `-d` 的完整命令 |
| Activity Monitor 里 CPU 很高 | Docker 在下载/解压镜像 | 正常，等它跑完 |
| 磁盘空间告警 | 镜像占地方 | 今天大概率不会遇到（本机可用 162GB） |
| `client.yml` 找不到 | 路径不对 | 用第 4 块步骤 1 的 `ls etc/` 确认位置 |

**绝对不要做的三件事**：

1. ❌ 不要执行 `docker compose down -v`（会删数据）
2. ❌ 不要执行任何带 `rm -rf` 的命令（尤其如果你不确定路径）
3. ❌ 不要为了「重试干净」去删除 Docker Desktop 的磁盘镜像或重置 Docker
