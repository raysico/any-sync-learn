# 网络与基础设施（Networking and Infrastructure）

## 概述（Overview）

`any-sync` 在本地设备与本地网络上无缝运行；但要在互联网上实现可靠协作，需要一层外部基础设施。纯 P2P 在公网上使用 STUN、ICE 及部分 IPv6 部署，约可达到 **80–90% 的连接率**，仍有 **10–20%** 的场景会因对称 NAT、严格防火墙或网络策略而失败。这些缺口需要中继（如 TURN），也凸显了稳健备份基础设施的必要性。

为此，`any-sync` 采用由同步提供商（sync providers）管理的**半联邦（semi-federated）基础设施**，在提供可选联网能力的同时不管理用户身份。该基础设施负责数据备份、全球可达性与跨网络协调。any-sync 建立在加密 DAG 数据结构之上，频道创建者可保留完全所有权，同时通过直连、自托管机器，或提供同步与备份服务的提供商，在设备之间同步变更。

**乐观同步（Optimistic sync）** 支撑高性能、可扩展的通信频道。频道在提供商切换期间仍保持可用，且没有切换成本。提供商被限制不得修改 ACL、加密密钥或频道内容；其唯一的"杠杆"是停止服务。**去中心化备份** 保障数据恢复，快照间隔由链上智能合约定义。频道所有者还可以选择多个提供商实现冗余，进一步降低风险。

> 注：多提供商支持与去中心化备份正在开发中，预计 2026 年 Q2 发布（ETA 2Q 2026）。

## 联邦基础设施（Federated Infrastructure）

`any-sync` 的基础设施采用**联邦（federated）**方式。提供商被组织为"子网（Subnets）"，每个子网运行一组特定节点（协调、同步、文件、共识）。用户可自由选择使用哪个（或哪些）提供商；若希望完全独立，也可自行托管整套基础设施。

**提供商** 提供以下服务：

1. 频道在客户端之间的**同步与复制（Synchronization and replication）**
2. 频道数据（结构化对象与二进制文件）的**存储（Storage）**
3. 频道数据及用户身份/元数据的**备份（Backup）**
4. **网络协助（Networking assistance）**：将本地设备桥接到全球网络
5. 专业帮助的**工程支持（Engineering support）**

### 子网（Subnets）

**子网** 是由一个或多个提供商管理的一组节点。每个子网拥有自己的协调节点，并运行一组特定配置的同步、文件与共识节点；这些节点由描述网络拓扑的"子网配置（Subnet Configuration）"统一串联。

## 节点类型（Node Types）

`any-sync` 基础设施包含四种主要节点：**协调节点、同步节点、文件节点、共识节点**。

### 1. 协调节点（Coordinator Nodes）

协调节点处理子网内的发现与编排：

- **子网拓扑**：识别子网内运行的同步、文件与共识节点。
- **配置分发**：维护"子网配置"并与所有节点/客户端共享。
- **频道路由**：使用一致性哈希将每个频道的 ID 映射到适当的同步节点；客户端向协调节点查询频道存储在哪里。
- **子网授权**：签署频道头（Channel headers），允许频道使用该子网进行同步与存储。

### 2. 同步节点（Sync Nodes）

同步节点负责存储与交换频道数据：

- 客户端从协调节点获得子网详情后，安全连接到指定的同步节点。
- 每个频道通常驻留在多个同步节点上，以实现冗余与可用性。
- 同步节点表现为"常在线对等体（always-online peers）"，任何离线设备之后都能取回错过的更新。

### 3. 文件节点（File Nodes）

文件节点处理较大二进制数据的存储与检索：

- `any-sync` 使用基于 **IPLD** 的数据结构存储文件。
- 客户端请求文件时，若经授权，文件节点即提供数据。
- 客户端若本地持有数据，也可通过 LAN/P2P 直接共享文件。

### 4. 共识节点（Consensus Nodes）

共识节点确保 ACL 拥有单一、一致的真值来源。虽然大部分协作可以完全离线完成，但 ACL 变更（如添加/移除成员）需要共识以避免冲突：

- 使用 **RAFT 协议**处理并发修改、节点故障及其他分布式系统边界情况。
- 同步节点提交已签名的 ACL 变更；共识节点验证它们。
- 验证后的 ACL 状态以子网"网络密钥（Network Key）"签名，并传播回所有同步节点。
- 未来，部分或全部共识逻辑可能迁移到区块链上，进一步去中心化信任。

## 对等体发现（Peer Retrieval）：从本地 P2P 到全球协作

### 本地 P2P（Local P2P）

`any-sync` 支持纯本地协作。通过 mDNS：

1. 设备在局域网广播对 any-sync 对等体的查询。
2. 响应的设备共享其 IP 地址。
3. 请求设备直接获取授权频道与文件，无需外部服务器。

### 全球网络（Global Networks）

面向互联网规模的协作：

1. 客户端向**协调节点**查询负责其频道的**同步节点**。
2. 安全连接该同步节点以获取更新并推送新数据。
3. 文件来自指定的**文件节点**。

当 NAT、防火墙或策略阻断直连时，**回退中继机制**确保连通，设备仍能交换数据。

### 混合模式（Hybrid Mode）

设备可将本地协作与远程基础设施结合。例如：

- **设备 A**：可访问互联网，与远程同步/文件节点通信。
- **设备 B**：无互联网访问，但与 A 处于同一局域网。

设备 A 充当**桥（bridge）**：将 B 的更新转发到互联网同步节点，并将全球变更通过本地 P2P 中继回 B。

## 可扩展性与负载分配（Scalability and Load Distribution）

### 轻量级客户端连接（Lightweight Client Connections）

在每个客户端上运行完整 DHT（分布式哈希表）会以数千连接淹没资源受限设备（如手机）。`any-sync` 通过以下方式避免：

- **限制客户端对等体**：客户端只连接一小群稳定对等体，通常是同步节点。
- **协调者提供的拓扑**：协调节点决定哪些同步/文件节点处理用户的频道。

这降低了开销，同时保证可靠、可扩展的网络。

### 两层哈希（Two-Layer Hashing）

`any-sync` 使用两层哈希均匀分布负载：

1. **模哈希（Modular Hashing）**：频道 ID 哈希后映射到"分区（partition）"，快速关联到主节点。
2. **一致性哈希（Consistent Hashing）**：每个分区被哈希到节点环上，环上最近的节点承载该分区。节点加入或离开时，分区平滑重排（reshard）以平衡负载。

若节点过载，附加的启发式算法会重新分配分区，以保持系统在规模上的高效。

## 总结（Summary）

`any-sync` 提供本地优先与可选全球基础设施的强大混合：

- **本地 P2P**：同一网络中的设备相互发现并共享数据，无需外部依赖。
- **联邦提供商**：基础设施"子网"提供全球可达性、备份与一致的访问控制。
- **稳健的节点类型**：协调节点管理拓扑与路由；同步节点存储与交换数据；文件节点处理二进制；共识节点维护 ACL 的单一真值来源。
- **高效的负载处理**：客户端避免沉重的 DHT 职责；负载通过模哈希与一致性哈希在同步节点间分布。
- **灵活的信任模型**：提供商无法修改频道加密或 ACL；它们只提供存储与中继服务。切换提供商简单，冗余提供商提升可靠性。

从纯 LAN 离线协作的小团队，到需要随时可用基础设施的大型组织，`any-sync` 在维护隐私、安全与可扩展性能的同时，适配多样化的使用场景。
